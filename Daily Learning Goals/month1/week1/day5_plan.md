## 📗 **Day 5: Business Requirements & Data Documentation**

### **Conceptual Questions**
- What are **business requirements** in the context of data projects?  
- Why is it important to translate business needs into **data requirements**?  
- What is a **data dictionary**?  
- What are the key elements of a data dictionary (field name, type, format, description)?  
- How does documentation help in **data quality** and **team collaboration**?  
- What is the difference between **technical documentation** and **business documentation**?  
- Why do BI developers and data engineers need strong documentation skills?

### **Practical Thinking Questions**
- How would you document a customer dataset (fields, types, formats)?  
- What happens if business requirements are not clearly defined?  
- How do you ensure that documentation is **understandable** for both technical and non‑technical people?  
- How does a data dictionary prevent errors in reporting?

### **Hands-On Practice Questions**
- Create a **data dictionary** for a sample dataset (e.g., employee table).  
- Document business requirements for a simple project (e.g., sales dashboard).  
- Write a short description of each field in a dataset (name, age, salary, joining_date).  

### **Reflection Questions**
- Can you explain why documentation is critical in data projects?  
- Can you prepare a simple data dictionary without guidance?  
- Can you connect business requirements to data fields in a dataset?
