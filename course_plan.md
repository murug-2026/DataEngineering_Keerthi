# Six-Month Data Engineering and Business Intelligence Job Readiness Programme

**Excel → Data Quality → Power Query → ETL → SQL → Database Design → Data Modelling → Power BI → Data Warehousing → Cloud Fundamentals → End-to-End Projects.**


# Training Strategy

<details>
<summary>Target job roles</summary>


This training is aimed to make you ready to pursue any of these entry level positions:

| Job Role                    | Skills Required                     | Priority  |
| --------------------------- | ----------------------------------- | --------- |
| Junior Data Engineer        | SQL, ETL, data pipelines, databases | High      |
| BI Developer                | Power BI, SQL, data modelling       | Very High |
| Power BI Developer          | Power BI, DAX, Power Query          | Very High |
| Data Analyst                | Excel, SQL, Power BI                | High      |
| ETL Developer – Junior      | ETL, data integration, SQL          | High      |
| Reporting Analyst           | Excel, SQL, Power BI                | High      |
| Junior Data Quality Analyst | Data quality, validation, SQL       | Medium    |

You should prioritise **BI Development + Low-Code Data Engineering** rather than attempting to aim for a conventional software-oriented Data Engineer.

Traditional Data Engineering positions often require Python, Spark, orchestration frameworks and cloud programming. Those can be learnt later, but should not dominate this programme.

</details>

<details>
<summary>Technology Stack</summary>

Avoid focus on too many technologies. You should become proficient in a small number of tools.

| Area                    | Recommended Technology            | Importance    |
| ----------------------- | --------------------------------- | ------------- |
| Spreadsheet             | Microsoft Excel                   | Essential     |
| Data Transformation     | Power Query                       | Essential     |
| Database                | SQL Server                        | Essential     |
| Query Language          | SQL                               | Essential     |
| Visualization           | Power BI                          | Essential     |
| Data Modelling          | Power BI / SQL Server             | Essential     |
| ETL                     | Power Query / SSIS concepts       | High          |
| Cloud Data              | Microsoft Fabric / Azure concepts | High          |
| Documentation           | MS Word / Markdown                | Essential     |
| Version Control         | GitHub                            | Medium        |
| Programming             | Basic Python (optional)           | Low initially |
| Secondary Visualization | Tableau                           | Optional      |

Let us predominantly focus on Microsoft Technologies. 

The combination of Excel + SQL Server + Power Query + Power BI + Microsoft Fabric provides a coherent learning path.

Is is not suggested to learn both Tableau and Power BI in depth. 
Power BI should be the primary visualization platform. Tableau awareness is good to have

</details>

<details>
<summary>Six-Month Curriculum Structure</summary>

I recommend dividing the 24 weeks into six learning phases.

| Month   | Learning Phase                       | Expected Outcome                              |
| ------- | ------------------------------------ | --------------------------------------------- |
| Month 1 | Data Fundamentals and Excel          | Understand and manipulate business data       |
| Month 2 | Advanced Excel and Data Quality      | Clean, analyse and validate data              |
| Month 3 | ETL and Power Query                  | Build low-code data transformation pipelines  |
| Month 4 | SQL and Database Engineering         | Design databases and retrieve data using SQL  |
| Month 5 | Power BI and Data Visualization      | Develop professional BI dashboards            |
| Month 6 | Data Engineering, Cloud and Projects | Build end-to-end data solutions and portfolio |

The following is the detailed weekly plan.

</details>

<details>
<summary>Journaling</summary>

Maintain a technical learning diary using a consistent format. This should not be replica of the documentation you go thruough. Just a diary to remember key points and techniques.

For example:

**Topic: SQL Joins**

1. What did I learn today?
2. What problem does this concept solve?
3. Why is it required in the IT industry?
4. How does it work?
5. What are the different types?
6. What are the practical applications?
7. What mistakes can occur?
8. What did I implement today?
9. What challenges did I face?
10. What did I learn from those challenges?

The idea is to develop the ability to explain technical concepts, not just execute commands.

# What We Would Deliberately Avoid

We will avoid overwhelming with programming. We will discuss only these:


| Technology / Concept          | Recommendation                                       |
| ----------------------------- | ---------------------------------------------------- |
| Python                        | Introduce basic concepts only after SQL and Power BI |
| Advanced Python libraries     | Later, if required                                   |
| Apache Spark                  | Conceptual introduction only                         |
| Hadoop                        | Conceptual introduction only                         |
| Basic Linux commands          | Limited Operations                                   |
| Tableau                       | Optional introduction                                |

There are three things we should not compromise on:

1. **SQL proficiency:** must become comfortable writing SQL independently.
2. **Data modelling:** must understand how databases and analytical models are structured.
3. **ETL concepts:** must understand how data is extracted, transformed, loaded, validated and refreshed.

These are foundational to the target career path.

# Main Considerations to Make this program Successful


**1. Work on documentation from Week 1.**

Do not wait until the final month to create documentation. Every week should include data dictionaries, process diagrams, technical notes, requirements documents and implementation records.

This will help to develop an engineering mindset.

**2. Give greater importance to SQL and data modelling.**

You should spend time on SQL and database concepts through continuous practice during Months 4, 5 and 6, even after the formal SQL module is completed.

**3. Make every month produce a working project.**

The objective you should have is to build a portfolio progressively, not to complete six months of theoretical training and then start practical work.
